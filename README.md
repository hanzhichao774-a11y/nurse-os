# 护语者 V1 Demo

依据 [需求文档](./护语者Demo需求文档.md)实现的护患沟通实训：选病例、与王阿姨实时对话、查看五维评分报告。患者只使用固定病例信息，不提供诊断或用药建议。

同一服务器还部署了独立的高校教师资格笔试刷题工具，两个应用互不影响。

## 打开演示

将项目部署到配置好 LiveTalking、MediaMTX 和 SoulX-FlashHead 的 GPU 服务器后，运行 `bash /root/start.sh`，再打开服务器 6006 端口的 `/demo/`。若通过 AutoDL 公网映射访问，请在 6006 的 HTTPS 地址后添加 `/demo/`。`/demo` 已配置为相对跳转至 `/demo/`。

两位患者的 SoulX 画面和 PCM 声音均通过同源 WebSocket 传输。手机进入病例的触摸动作同时解锁 WebAudio，无需另点播放。部署细节见 [后端说明](./demo_backend/README.md)。API 密钥只保存在服务器 `/root/demo_backend/.env`，没有写入网页或本项目代码。

## 高校教师资格刷题工具

- 部署入口：服务器 6006 端口的 `/exam/`
- 独立路径为 `/exam/`，原护理实训继续使用 `/demo/`。
- 题库由用户提供的 Excel 转换，共 1954 题：高等教育学 765 题、高等教育心理学 778 题、职业道德与法规 411 题。
- 支持顺序练习、随机练习、模拟考试、答题卡、错题本、收藏、进度统计和断点续练。
- 使用邀请码注册和用户名密码登录；Cookie 有效期 7 天，并启用 `HttpOnly`、`Secure`、`SameSite=Lax`。
- 错题、收藏、进度及未完成练习保存在服务器并按用户 ID 隔离。邀请码应在部署环境中生成和保管。
- 题库转换脚本为 `deployment/parse_exam_workbook.py`。

## 当前版本的数字人

- **王阿姨和林先生**均使用独立的 SoulX-FlashHead Lite 实例实时生成 512×512 全画面。上传视频只用于提取人物参考帧和授权声音，不在页面中循环播放。
- 两位患者各有 50 条审核过的病例回答和 1 条开场白。DeepSeek 依据完整历史选择回答编号，不能改写台词；页面文字、浏览器音频和口型驱动共用同一内容与同一份 PCM。
- LiveTalking/Wav2Lip 继续作为 SoulX 不可用时的会话级回退。
- 浏览器先确认 WebAudio 已经运行并排好声音，再让 SoulX 按 160 ms 分片和真实时钟节奏生成口型；1.3 秒声音提前量用于覆盖首批画面推理缓存。打断时同时停止浏览器声音、后端语音和渲染队列，并立刻回到闭口参考帧。
- [VoxEMW](https://github.com/emwstudio/VoxEMW) 提供了 SoulX Lite 分段生成和 25 FPS 节奏控制的成熟参考。本项目固定参考提交 `63560df`，并增加了音频就绪握手、flush 代际检查、闭口复位和护士 Demo 的 Provider 接入；相关 MIT 许可保存在 `deployment/VoxEMW-LICENSE`。

## SoulX 复验材料

- 独立画质测试覆盖静音、短句和 33.8 秒长语音，三段均为 100% 唯一帧；长语音得到 884 帧、平均 24.02 FPS。
- Chrome 十轮实时验收中，60 秒静音采样无重复帧，10/10 轮完成音频调度和口型生成，开口耗时 1.96–2.10 秒，打断耗时 35 ms。
- 移动 WebKit 十分钟验收中，同一会话持续 600.5 秒，20 次画面采样全部不同；4/4 轮在 1.98–2.01 秒出声。
- 完整 JSON、截图、PDF 和录屏保留在本地 `artifacts/`，因包含大型文件和演示素材，不纳入公开仓库。

## 当前边界

SoulX Lite 输出为固定 512×512 头肩画面，不能等同全身动作或电影级数字人。两位患者采用各 50 条固定病例应答来保证现场稳定性，不承诺开放域任意文本。实体手机和麦克风仍应在比赛现场网络环境试说一句；语音输入不可用时可直接打字。
